# 侧边栏生命周期诊断

构建：`npm run build:diagnostic`。

加载目录：`.output-diagnostic/chrome-mv3-diagnostic`。
扩展名称：**页脉 · 生命周期诊断**。此构建使用独立输出目录，没有开发热更新；普通构建不启用诊断。

## 第一轮：只打开和关闭

1. 手动打开 Chrome 扩展管理页，暂时停用其他页脉版本，不要卸载。
2. 开启开发者模式，用“加载已解压的扩展程序”选择上述目录。
3. 新目录加载的诊断扩展有独立本地数据；这一轮不需要配置 WorkOS、导入历史或连接认知目录。
4. 打开一个普通文章网页并刷新，固定在此页面，不切换网页、不划词、不发送消息、不上传文件。
5. 按 Shift+Esc 打开 Chrome 任务管理器，记录基线。优先记录含“页脉”的任务；可右键表头显示进程 ID。不要把所有行的内存相加，同一进程可能显示为多个任务。
6. 打开诊断侧边栏，等待 5 秒，点右上角 × 关闭，等待 60 秒。重复 5 轮。
7. 第 5 轮等待结束后记录任务管理器中的任务名称、PID、内存和 CPU，再打开一次诊断侧边栏，点击左下角“导出诊断”。这一次打开是导出操作，不计入测试轮次。
8. 保留下载的 `yemai-lifecycle-*.json` 以及前后两次截图，交回分析。

不要在导出前重启 Chrome、重新加载或停用诊断扩展，session 日志可能被清除。测试时关闭页脉的 DevTools；检查 Service Worker 会影响它的退出行为。

## 记录与限制

- 记录实例随机 ID、时间、打开/关闭事件、后台连接计数、应用资源计数和浏览器版本。
- 不记录网页 URL、正文、对话文本、文件名、连接凭据。
- 使用 session 存储；单个上下文最多 120 个事件，最多保留 48 个上下文。没有轮询或心跳。
- 存储调用会短暂延长后台活动，所以每轮等待 60 秒；日志仍有观察开销，不能作为严格性能基准。
- 关闭时的异步日志可能来不及写入。缺少 pagehide 不是泄漏证据，需结合后台断连事件和任务管理器。
- 消息运行状态与上传 Set 的数量属于应用计数，不能等同于真实网络连接数或操作系统进程数。
- 第一轮没有原版历史数据，只用于隔离基础开关路径；若无法复现，再设计包含历史、流式回答或上传的后续场景。

导出完成后可停用诊断扩展，重新启用日常使用的页脉版本。
