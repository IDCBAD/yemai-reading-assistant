# 批量阅读与子任务详情

2026-10-03：代码合入 `main`，未创建新版本 Release。用户已确认本轮界面可交付；界面使用真实组件验证，WorkOS 事件使用模拟数据验证，真实子任务字段尚待核验。

## 使用方式

1. 在输入区点击叠页图标“批量阅读”。粘贴链接，每行一个；编号和 Markdown 链接也可识别。
2. 核对选择，可修改显示名称。每组最多 5 个网页；重复链接合并，不接受包含账号密码的地址。
3. 点击“加入当前问题”。保留已有问题、收藏、划词和附件，默认排除当前页。需要当前页时可以手动包含。
4. 输入阅读问题并发送。空问题会使用“分别提炼核心内容，再说明这些材料之间的联系。”作为可见的用户提问。
5. 链接随会话保留，后续提问可继续使用，也可逐项排除或移除。每次发送保存独立快照，修改草稿不会改写旧回答的来源。

接口返回 `task` 活动时，运行过程显示为可点击的子任务卡片。详情浮层最多 380px 宽、460px 高，同时受窗口高度 66% 限制；正文内部滚动，底部切换按钮固定。支持上一个、下一个、关闭按钮、点击背景和 Escape，关闭后返回原卡片。

## 与 Agent 的分工

插件保存链接、选择状态、问题和来源，通过 `YEMAI_CONTEXT_V1` 的 `link` 引用与可选 `reading_task` 表达阅读意图，发送时仍使用 Markdown 文本。阅读指令要求每篇围绕同一个问题处理，返回依据、来源和失败或不完整之处，再由当前 Agent 综合。

如果 Agent 支持 task 或子智能体，则请求其分篇处理，支持并行时并行；否则由当前 Agent 阅读。不创建第二个主 Agent，不绑定新的调度接口，也不保证 Agent 一定启动子任务。插件没有抓取这些链接的正文；是否能读取登录页面、长页面或受限页面取决于连接的 Agent，不能据标题声称已经读完。

界面消费通用的 `RunActivity.kind = subagent` 和 `SubagentSnapshot`，通用类型位于 `src/shared/agentActivity.ts`。WorkOS 字段转换仅在服务层。更换底层 Agent 时可继续使用链接选择、发送快照、来源和详情组件；需要让新连接返回相同的活动信息。

## 子任务内容的来源与限制

当前 WorkOS 适配读取 `message.part.updated` 的 tool/task：

- 标题：明确的任务 `state.input.description`，或既有标题。
- 类型、任务说明：`state.input.subagent_type` 和 `state.input.prompt`。
- 子会话标识：`state.metadata.sessionId` 或 `sessionID`，只保存有限长度的标识字符串。
- 返回结果：完成状态的 `state.output`；存在 `<task_result>` 时取其中正文，否则使用返回文本。

旧版 `tool.*` 事件中的 task 同样可以显示卡片；没有明确的详情字段时保持为空。通用工具仍只展示名称、状态和耗时。任务说明限制 12,000 字，结果限制 24,000 字，截断时有提示。不保存完整事件、普通工具原始参数、推理内容，不从主回答补造子任务结果。

这些任务详情字段目前属于**适配实现和模拟验证范围**，用户截图证明主 Agent 可以启动子任务，但截图不能确认 API 返回字段。尚未增加子会话历史读取接口，也没有子会话实时工具轨迹。若当前通道只返回任务名称，点击后会显示“当前接口未返回子任务结果。”；不能声称与 WorkOS 原生完整子会话浏览等价。
