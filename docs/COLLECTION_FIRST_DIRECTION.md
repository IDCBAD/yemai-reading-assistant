# 页脉产品方向：先收藏，再形成认知

> 决策状态：已确认并进入实现
> 决策日期：2026-08-31
> 取代范围：取代“由 Agent 在对话中自动发现认知候选并直接写入本地目录”的默认路径；独立本地目录 ADR 继续有效。

## 核心判断

Agent 不应在捕获阶段决定什么是用户的个人认知。页脉先提供低成本、确定的收藏动作；用户以后再从收藏卡片主动发起认知形成。

```text
AI 回答
→ 用户收藏完整回答，或划选结论收藏片段
→ 收藏卡片保存在浏览器本地
→ 未来由用户选择一张或多张卡片发起认知形成
→ 用户最终确认
→ 写入独立 Markdown 目录
```

## 当前产品边界

- 完整回答和回答片段统一进入“收藏”，但保留类型区别。
- 收藏不调用 Agent，不要求填写表单，也不写入认知目录。
- 同一回答可以保存多个不同片段；相同片段按来源消息与规范化正文去重。
- 划词浮层同时保留“收藏片段”和“引用追问”。
- WorkOS 的通用 `question` 交互继续可用，但回复不再触发本地认知写入。
- Agent.md 只约定页脉上下文、来源处理和信任边界，不再要求 Agent 自动提出认知候选。
- 本地知识目录继续支持选择、权限恢复、连接探针和既有受管文件读取；收藏不会自动改写目录。
- 既有认知 Markdown 和历史回执保留，不因本次重构删除或迁移。

## 后续认知入口

未来讨论认知形成时，输入应来自用户主动选择的收藏卡片，而不是来自回答结束时的 Agent 猜测。认知工作流应作为独立模块消费卡片，在最终确认前不写文件。

本阶段不决定认知模板、合并规则、卡片数量上限、Agent 提炼提示词或认知演化交互；这些问题在收藏真实使用一段时间后另行设计。

## 验收标准

- 完整回答和划选片段都能一键收藏并在重启后恢复。
- 多个不同片段可以来自同一回答，重复片段不产生重复项。
- 收藏面板明确区分“完整回答”和“回答片段”。
- 收藏、普通对话和通用 `question` 都不会创建或修改认知 Markdown。
- 本地目录连接可以恢复，既有文件保持不变。
- 卡片详情在窄 Side Panel 中不发生正文右侧裁切；宽表格和代码只在自身区域横向滚动。
