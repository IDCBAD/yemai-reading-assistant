# 使用独立 Markdown 目录保存认知

页脉将用户主动确认的认知保存到用户明确选择的独立本地目录，一条认知对应一个带稳定 `yemai_id` 的普通 Markdown 文件。推荐从空目录开始；若用户选择已有内容的目录，页脉必须先明确说明不会导入现有文件，并在用户再次确认后才可连接。页脉只管理自己创建且结构有效的认知文件，可以重新读取和索引用户对这些文件的外部编辑，但不导入现有 Obsidian 笔记、不改写其他 Markdown，也不做双向同步。这个选择让页脉专注于认知的形成、重遇和修订，让 Obsidian 充当首个文件消费者，同时保证知识资产不被页脉数据库或单一工具锁定。

## Considered Options

- 只保存在页脉的内部数据库：实现简单，但长期资产难以直接阅读和迁移。
- 直接接管现有 Obsidian 知识库：冷启动更快，但会混入未经用户确认的剪藏、摘要和他人观点。
- 页脉与 Obsidian 双向同步：编辑自由度最高，但需要处理身份、冲突、重命名和结构推断，超出首个认知闭环的验证范围。
- 每个主题维护一个持续增长的文件：适合阅读，但新认知插入位置和并发编辑会让自动维护变得脆弱。

## Consequences

目录权限能否跨 Side Panel 和浏览器生命周期稳定恢复，必须先通过技术原型验证。认知候选在用户确认前不得写入目录；主题页、全局关系图和其他视图应从单条认知派生，不能成为需要双向维护的第二份事实来源。
