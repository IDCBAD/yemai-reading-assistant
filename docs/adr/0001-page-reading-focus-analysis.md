# 以文章分析任务准备意群阅读

真实试用发现，按鼠标悬停逐段创建 WorkOS 会话会把普通阅读动作变成不可见的远端任务，并反复承担启动成本；短时取消还可能中断部署或思考。用户已认可整篇准备方案，并指定 `https://browser-use.com/posts/browser-agents` 作为试用页面。现已实现：用户主动开启后，对确定的正文快照准备一次文章分析任务，完成并检查结果后进入意群阅读，之后悬停只进行本地聚焦和显示。代码实现不等于真实 WorkOS 的稳定性和耗时已经验收；此前超时的具体远端原因仍需真实调用证据。

普通篇幅正文一次提交，输入携带段落标识，输出携带对应段落的精确原文片段及类型，避免重复回传整篇文章，也不依赖模型计算全文偏移。输入上限为 60,000 个 UTF-16 单元、240 段、单段 16,000 个单元；超限时说明暂不支持完整分析，不静默截断、不自动拆成许多新会话。输出最多 240,000 字符、每段 32 个片段、全篇 1,000 个片段。每个段落需明确返回结果或空结果，重复片段必须提供准确出现序号；遗漏、错误或无法定位的段落仅提供聚焦，并如实显示覆盖情况。未知或重复段落编号拒绝整份结果；全篇无有效段落判为失败。没有 CSS Custom Highlight API 时只提供聚焦，不调用 AI。

准备时退出辅助阅读只关闭界面，任务在后台继续并保存结果；另设明确的“停止分析”。同一份正文的重复开启和多个标签页复用同一在途任务或已完成结果。结果按归一化页面身份、段落编号与正文顺序、分析版本、传输类型、Agent 和固定 API 地址生成 SHA-256 标识，持久保存纯数据，不保存 DOM 节点、Range 或凭据。仓库复用 IndexedDB 的 `meta` 表，保留最近 20 个已完成任务，在途和状态不明的任务不因此删除。重新显示前核对原文，退出不清除有效结果；缓存不进入本地知识备份，不创建本地聊天记录。

任务阶段与远端标识独立保存。扩展重载、浏览器关闭、断流或停止请求被接受都不等于远端已结束；状态不明时不自动重复提交。重载后未完成的任务转为状态不明，不声称能恢复远端执行。只有已确认失败或停止才提供显式重试。Internal v2 可请求停止，接受请求后若无终态证据仍记为状态不明；Public v1 无远端停止方法，明确提示后继续等待原任务结果并缓存。未提交的准备可以结束为已停止。全局同时准备最多两个文章任务。

界面区分识别正文、准备分析、接收结果、检查结果及可阅读状态。等待时暂停意群交互，不淡化正文，保留普通网页阅读、滚动和退出能力；扫描只提供短暂反馈，不用持续动画或虚构百分比表示远端进度。当前为远端创建与分析设置 5 分钟候选等待上限；它不是根据真实服务测量得出的完成承诺，仍需实际文章调用后调整。超过上限结束本地等待并报告远端状态不明，不自动重新提交。

本轮已完成共享数据、持久仓库、后台任务、网页交互及模拟预览。核心单元与回归测试 89 项、预览浏览器检查 14 组、扩展整篇流程检查 9 组、TypeScript 和构建已通过。针对指定目标站的自动化采用原始 HTML/CSS 快照及模拟 WorkOS，识别 60 个阅读块、10,124 个字符，不代替真实服务验收。首次等待、实际停止行为、结构化结果质量和阅读效果仍需真实试用确认。已有词库 CRLF 导致的两项哈希检查失败另见 `docs/READING_FOCUS_MODE.md`，本次未修改数据或放宽检查。
