# OpenRouter 四页辅助阅读实测

日期：2026-10-23（Asia/Shanghai）。本轮按用户要求检查3–5个页面，实际选择4页。正式提示词保持 `page-reading-v3`，不更换模型配置，不调整生产颜色或解析规则。

## 结论

已完成三页的主要规则、条件与结果大体可读，不能把这些结果笼统说成“分析不准确”。当前较明显的问题是颜色角色的教学含义：紫色混合了触发前提、适用范围与让步背景；少量复杂句只突出信息，结构层次不够清楚。另有一页在返回部分 JSON 后接收异常，不能评价完整质量。

这轮要分别回答四个问题：正文是否进入模型、返回是否精确保留原文、类别是否有助于理解关系、网页着色是否对应返回。通过原文定位不等于语义正确率，合理留白也不是漏分析。

## 输入检查

四页实际渲染 DOM 均选中 `#content.mdx-content`，继续使用生产提取器，保留跨链接及内联代码的原文顺序。Zero 的13块与用户返回的段落编号相符，主要正文及例外内容都在本次输入里，未发现导航、反馈问句或聊天输入框混入。用户历史31个意群与本次新采集原文对照也能13/13精确定位；历史请求的完整快照、模型设置没有独立记录，因此不能宣称严格同输入重复实验。

输入并非把全部页面文字发送给模型：代码块、表格单元格和部分短标题不在训练输入中。Fallbacks 列表的 `Rate-limiting`、`Downtime` 因当前长度/词数过滤未进入独立阅读块；首段和后面的长段仍包含这些概念，所以本轮没有改变这两种失败的总体说明。Structured Outputs 的部分单词型 provider 名称也被过滤。这些是输入范围的已知限制，不应写成模型漏选。

## 用户提供的 Zero 返回如何评价

用户历史返回的条件与结果主干多数合理，尤其是否收费、否定、AND/OR、`once` 和 `only` 等限制基本可读。最清楚的分类疑点是 p12 把 `On your activity page` 这种展示位置标为条件；本轮新返回将它标为 detail。只能报告两份返回有差异，不能把一次新结果当作已修复或已经证明同输入不稳定。

以下内容不应机械判错：

- p8/p9 的 TTS、图像请求是规则适用范围。当前提示词允许 condition 表示实际限制，因此归为紫色有解释空间；它们与页面位置不同。
- p4/p5 是承接上段结果的条件列表，只有 condition 不等于缺少主干。
- p10 两段 core 跨括号例子共同组成并列主语和谓语，整体可以读通；不能要求每个被插入语切开的蓝色片段各自都是完整句。
- 长段选择少量关系、标题和标签留白，符合训练目标。原文中存在某句而没有着色，不能单独作为错误证据。

## 四页人工观察

### Zero Completion Insurance

新结果正确保留了无输出/finish reason 条件、免收 token 费用的结果、有效输出定义以及辅助服务仍可能收费。p12 位置背景这次归入 detail，较符合教学预期。

p10 将“即使模型响应随后出错”标为 condition。它表达的是“发生该情况，前述结论仍成立”，与收费规则的触发前提不同。语法上它也可称让步条件从句，不能简单声称模型不懂语法；产品若用紫色表示触发/前提，就需要把让步归入补充说明或留白。p9 把多种失败状态与不计费结果合为较长 core，逻辑仍可读，但教学层次粗。

原文概述将无输出与空 finish reason 或 error 联合描述，后面的条件列表又把 error finish reason 单列。这个潜在措辞范围差异来自原网页；模型忠实摘录时不能算成模型新造规则，本报告也不据此解释实际账单政策。

### Models

重要含义保留得较好：省略参数时只返回文本模型、404的两个限制、分页默认值、条件全部匹配后生效、多项适用时后项优先、跳过未知条件、输出上限并非保证输出长度等。

p47 把“即使输入输出相同”标为 condition，与 Zero 的让步混入紫色是同类现象。p24/p25 某些引出价格例子的名词片段被标为 core，属于层次可改进；不适合按字数或单片段是否有主谓作硬性裁切。浏览方式中相近短语被赋予不同类型，也会降低读者对颜色的预期。

### Model Fallbacks

本轮未发现与上述同等级的明确关系问题。主模型失败与回退模型失败的不同后果、免费模型回退到付费模型的条件、保持免费的目的、只接受 model 字段、禁止组合参数和数量上限均被保留。跨插入例子的主谓蓝色片段可以共同理解；部分隐含条件用整条规则作 core 也合理，不必强迫所有业务规则都拆成紫色。

### Structured Outputs

未取得完整响应，不作全文质量结论。只凭开头几组看起来合理，不能声称这页分析成功。此次失败已保留输入、部分正文与阶段，后续可在 WorkOS 检查原会话。

## 网页映射与视觉回放

使用本轮真实持久化结果回放保存的网页 DOM，不再请求模型。生产正文发现与提交快照逐字比较，147个意群均通过 DOM Range 文本核对。回放使用隔离浏览器及公开静态样式，不是用户当前原标签页验收；unknown 页面明确跳过。

最终三页的147个 Range 文本检查、15个指定悬浮检查均通过；每页退出后高亮数量为零，body HTML 与链接均逐字恢复。每页仅调用一次本地结果准备函数，回放不调用 WorkOS。主代理另行查看 Zero p10、Models p47、Fallbacks p8 的完整样式截图：普通正文中的条件、主干和目的可以区分，返回中的让步分类问题也如实显示。Models 原有蓝底提示框内的颜色区分弱于普通正文，是后续视觉适配可补充的场景；本轮未改生产配色。

工具验证期间修复了两类测试副作用：禁用全部 JavaScript 连注入的悬浮回调也禁用，因此改为 CSP 和请求拦截只禁网站脚本；Playwright 默认隐藏光标会给原页面输入框留下空 style 属性，因此截图改为保留光标状态。首轮沙箱截图未取得站点 CSS；允许隔离浏览器加载公开静态资源后，已重新执行并取得正常布局、字体和颜色。最终退出检查没有忽略 DOM 差异，也没有为测试修改生产代码。

## 后续建议

1. 保留四色，先明确紫色的产品约定。建议用于触发、前提和有条件的限制；位置、一般语境和让步默认用 detail 或留白。对适用范围选一种一致约定，不能让读者猜颜色含义。
2. 在提示词中加入少量成对例子，区分位置/范围、真正触发、让步仍成立；只改措辞和选择规则，不在前端靠 if/when 等关键词强行改标签。
3. 复杂段落优先选一两组完整关系，保留否定、only、AND/OR、必要补语。不要为缩短蓝色片段而破坏共享谓语，也不要把多着色当作更准确。
4. 用本轮三篇作已知回归，再选择未参与提示设计的页面复测。没有对照和留出样本前，不称已提高语义准确率。

本轮没有修改生产提示词或颜色类别，先保留完整基线。语言评审由主代理及独立审查完成；官方文档预审详见 `openrouter-reading-quality-source-review-2026-10-23.md`。

收尾时对本轮78个报告、输入、返回及回放文件检查已授权连接的凭据值，未发现包含；临时配置读取和批量调用辅助脚本已移除。
