# 辅助阅读样本采集与真实 WorkOS 测试

日期：2026-10-23（Asia/Shanghai）

## 结论

目前至少有三个独立问题：正文识别存在确定的遗漏；模型在干净原文上仍会混淆关系或改变标点；收到正文后也可能因连接异常无法确认远端结束。不能只调整提示词，也不能把所有现象归因于 WorkOS 沙箱。

本次已修复一个有真实 DOM 证据的正文遗漏：OpenRouter 文档将段落渲染为 `span[data-as="p"]`。原实现只认识 `p/li/...`，漏掉正文后只剩“Was this page helpful?”。最小修改是在 MDX 正文区域支持 `data-as="p"` 和 `data-as="li"`；保留原有隐藏内容、控件排除与嵌套去重规则。生产提示词仍为 v3，实验提示词没有合入插件。

## 已取得的材料

- 只读导入用户桌面目录中的4份记录，保留原始字节与 SHA-256；没有修改来源文件。
- 建立15个候选 URL 的清单，其中10个为 OpenAI 页面或文档，含研究长文、短文、目录和 PDF 边界。候选不等于已采集或已调用模型。
- 真实浏览器采集到 arXiv Mercury 摘要页、OpenClaw Focus Weeks、OpenRouter Principles、GitHub Textfold 四个页面的 HTML、可见正文、生产提取快照和提示词。修复后的 OpenRouter 另用保存的真实 HTML 离线重放。
- 从六个 OpenAI 官方页面选出14个完整原文段落，覆盖因果、条件、比较、限定、同位语、并列、研究结论和研究限制。它们是明确标注的混合来源语义样本，不是插件对 OpenAI 全文的实际提取结果。
- 发起5条受控 WorkOS 真实请求，使用现有 internal-v2 连接；每条对应一个明确的测试输入。没有对未确认结束的任务自动重发。

OpenAI 原文来源：[幻觉研究](https://openai.com/index/why-language-models-hallucinate/)、[MLE-bench](https://openai.com/index/mle-bench/)、[FrontierScience](https://openai.com/index/frontierscience/)、[对抗鲁棒性研究](https://openai.com/index/trading-inference-time-compute-for-adversarial-robustness/)、[科学协作实验](https://openai.com/index/accelerating-science-gpt-5/)、[Introducing dots](https://openai.com/index/introducing-dots/)。前五个属于研究样本，dots 另作用户关注的产品文章对照。

## 模型质量

正式 v3 在干净 OpenAI 原文上的具体问题：

1. **改变原文标点**：一个片段漏掉引号内的句号，导致整个段落无法精确定位；前端正确地拒绝高亮，而不是勉强匹配。
2. **把关系词当固定标签**：`as` 表示随变量变化时被标成原因；`The more…` 比较结构被标成条件。这些输入本身没有缺失。
3. **科学结论的力度可能变强**：选出推理算力提升鲁棒性的内容，却漏掉“初步证据”的报告语。原文没有被改写，但着色的注意力分配可能让读者忽略限制。
4. **复杂定义仍常整块归为主干**：FrontierScience 的两个赛道及各自说明都被放进 core，层次仍粗。

OpenClaw 这次返回还有独立的精确匹配问题：p17 把原文弯引号 `we’re` 改成直引号 `we're`。这与用户复制输入时的 JSON 损坏不同；是新返回本身的文字变化。

实验补充指令要求精确复制标点、根据实际含义判断原因/条件、保留科学限定、选更少完整教学单元。其14段全部通过定位，部分误分类减少，但出现明显代价：

- 14段按段落等权计算，着色均值从正式版51.0%升至62.0%；正式版的一个无效段按0计入，这不是纯粹的语义比较。
- 超过75%着色的段落从0个变为3个；单个主干最长从17词增至24词。75%和词数仅作观察，绝非运行时硬性裁切标准。
- 有一段几乎整段着色，并把主要论断纳入 detail；MLE 结果说明又合成较长 core。
- 比较结构未再被错误标为条件，但那句话被整句留白；这不证明模型已经理解它。

因此没有把实验版换成正式版。更严格的复制和关系说明值得继续研究，但不能用“定位14/14”替代阅读训练质量，也不能只优化一两个已知样本。

## 工具与验证

新增工具说明见 `scripts/reading-focus-corpus/README.md`：

- 本地案例导入：只读来源、内容摘要、明确缺失项，不修补不可靠原文。
- 网页采集：运行生产提取器，保存 HTML、根容器、快照、提示词；每次采集单独留档。
- 真实测试 CLI：默认不提交；显式执行时单次提交；按目标与提示词持久去重，改案例名也不重发；超时/异常只结束本地接收，保留未知状态。
- 汇总：定位、着色范围、过长片段、耗时和失败阶段；不输出未经人工判断的“语义准确率”。

已通过 TypeScript 检查、27项相关单元测试、3组真实调用工具的模拟回归（包括跨名称去重、并发、断流、超时和凭据不进入产物）、扩展生产构建。OpenRouter 的真实 HTML 修复前后对照和修正输入的7/7真实接口返回已取得。离线结构浏览器回归也已通过：MDX 的跨节点文字、嵌套列表只取一次，隐藏内容与控件段落不进入输入，最终选择正文而非反馈区。运行中曾发生浏览器冷启动超时，延长等待后通过，未将这些启动故障写成网站或插件问题。

独立 architect 审查已发起，但子代理因工作区额度不足退出；没有得到独立审查结论，不能声称完成双人审查。主代理已检查新增工具的提交次数、未知状态和凭据输出边界。实际凭据仅内存使用，不进入报告或测试输入；对77份生成的样本、返回和报告进行实际连接值比较，未检出凭据。读取连接的本次临时脚本在测试结束后移除，正式测试 CLI 不包含浏览器凭据提取功能。

## 下一步

1. 优先补正文识别与反馈：排除图片说明、书目工具等界面块；明确显示“识别到哪些正文”，无正文时给出可见提示。GitHub 的真实用户入口仍需复现。
2. 分别衡量“原文定位”和“读者是否能看出关系”：保留科学限定、原因和结果成对、主干完整、着色克制。不要只看总覆盖率。
3. 在更多未见过的文章上复测小幅提示词改动；本轮实验未达到替换正式版的条件。
4. 继续保留远端状态未确认的处理。收到合法 JSON 与确认远端结束是两件事；前者不足以自动重试或宣称任务完成。
