# 手动停止与 WorkOS 暂停

2026-10-08 本地实现，用户已报告暂停功能测试通过；2026-10-09 后台执行接入后，用户也已报告关闭侧边栏再打开任务不中断。2026-10-11 用户报告本轮测试暂无问题，能力纳入 `main` 进度整合提交；未创建新版本 Release。各项验证的具体范围仍以下方记录为准。

点击输入区停止按钮时，插件停止本地流式接收，并在内部 v2 模式对正在执行的远端会话调用：

```http
POST https://workos-api.yingdao.com/api/workos-agent-server/v2/conversations/{conversationUuid}/action/abort
```

请求没有 body。身份头沿用插件当前执行请求的 Access Token、Organization UUID 和 User UUID，后两者动态加密。不会保存或复用用户提供的示例凭据与会话 ID。接口依据来自用户在 WorkOS 前端点击暂停时捕获的请求；截图显示 HTTP 200，但未提供响应正文和远端工具实际停止记录。

## 行为

- 只在显式点击停止按钮时发送远端暂停；关闭侧边栏、清理工作区等默认中断不触发此接口。
- 读取页面、创建会话或建立订阅时若尚未提交问题，只取消本地准备，不暂停远端其它任务。
- 如果提交请求已经发出，先等待该提交的响应，再发送暂停，避免先暂停、后提交。手动停止后等待提交响应最多 10 秒；提交结果不明时尽力发送暂停并明确显示未确认。
- 已收到的正文和产物保留。界面分别显示本地停止、暂停处理中、WorkOS 已接受暂停请求和暂停未确认。接口接受请求不能证明所有工具已经停止，也不自动假设任务可以恢复。
- 当前执行 Promise 在暂停处理结束后才结束，所以同一会话的下一条排队问题不会抢先提交。暂停失败或提交结果不明时，未发送的后续排队问题保留在会话中并标为停止，不自动重新发送。
- 暂停请求使用独立的取消信号，最多等待 10 秒。重复停止不重复发送；HTTP 失败、JSON 业务失败、网络异常和超时都显示未确认。
- 重开时未取得响应的暂停记录恢复为未确认，不显示仍在暂停或已成功。
- 2026-10-09 后台接入后，点击停止再关闭侧边栏，暂停请求与结果保存继续由后台处理；隔离 Chromium + 模拟接口已验证延迟响应期间关闭页面。详见[后台执行](./BACKGROUND_TASKS.md)。
- 公开 v1 模式没有已确认的暂停接口，继续本地停止，并提示此限制。

## 验证

本地模拟测试覆盖暂停请求路径、空 body、动态身份头、成功与失败响应、超时、提交与暂停顺序、普通清理不触发暂停、同会话队列等待、结果提示以及状态恢复。通信测试使用合成加密实现，不能作为真实 RSA 或线上身份验证证据。

前一轮暂停相关 7 个测试文件 / 73 项测试、TypeScript 与差异格式检查通过，生产扩展构建通过。2026-10-09 身份加密改为 Worker 安全模块后，原 `jsencrypt` Node 环境失败也已消除；新增独立 RSA 密文测试。完整验证结果见后台执行文档。

真实验收需在已登录的 Chrome 扩展中发起耗时任务并点击停止，确认插件调用目标会话的 `/action/abort`、收到响应，以及 WorkOS 中该任务的实际状态；另检查已有正文/产物保留和同会话后续排队问题的行为。不要将 curl 中示例会话当作测试目标。

关闭侧边栏后继续接收结果已在后续后台任务中实现；提醒形式待讨论，断线重连和公开 v1 暂停仍未提供。
