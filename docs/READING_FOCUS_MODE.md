# 辅助阅读模式

当前 V2 的语义标签、固定搭配、三种显示模式和首次设置见 [辅助阅读 V2](READING_FOCUS_V2.md)。以下保留原版实现与历史验证说明。

辅助阅读保留原始网页和英文，在正文内提供段落聚焦、关键意群标记及主动查词。它不提供全文中文替换，也不声称颜色标记等同于完整语法分析或证明学习效果。

## 使用

构建扩展后，在 Chrome 扩展管理页重新加载 `.output/chrome-mv3`，并刷新要阅读的网页。在页脉侧边栏顶部点击眼睛按钮开启辅助阅读。插件识别正文后，对当前整篇文章准备一次分析任务；右下角显示准备、接收和检查等实际阶段。开始时有一次短暂扫描，它不代表远端进度，也不会循环播放直到任务结束。

准备期间仍可正常阅读、滚动和选词，但暂不显示段落淡化或意群高亮。结果返回并与原文检查后，进入意群阅读：移动鼠标立即切换当前段落，其他正文变淡，并显示本地已经准备好的意群。切换段落不会再发送分析请求。

蓝色表示核心信息，紫色表示条件，绿色表示原因或目的，橙色表示补充或例子。默认只标记关键片段，其他文字保留原样；具体标记范围取决于模型结果。

`page-reading-v3` 先选择值得展示的阅读关系，再切分意群。长多句段落通常选择一两个有教学价值的句子关系，普通叙述、重复信息和背景句保留原样；完整理解每句话不意味着每句话都必须着色。只在选中的关系内保留完整关键动作、必要宾语与补语、否定和情态含义，再区分条件、原因／目的及说明。平行的 API／脚本／Agent 选项不应遗漏关键动作；关系说明、目的与插入例子不应全部吞进蓝色主干。提示内有八个教学示例，其中五个多句示例明确留出整句不着色，也包含选择段落中间关系的例子；它们与文章数据分开，不产生额外调用。

长段落通常以约 30–65% 的着色为提示目标；超过约 75% 时，模型应重新选择要展示的关系，而不是裁短必要主干或只换成更多颜色。这些不是通用硬限制：短完整句、紧凑的多选项对照仍可高覆盖，独立标题与标签通常不额外着色。客户端继续只检查至少两个有效空白分隔词等形式条件，技术复合词、标识符和缩写不因标点拆成多个词。检查失败仍只让对应段落降级，客户端不通过连接词猜语法或自动改类别，也不为覆盖率强行裁剪原意群。

高亮会读取当前段落及祖先实际的背景、透明层和主要文字颜色，再选择颜色与强度。深色页面增加辨识度，浅色页面保持柔和；同页不同底色的阅读块分别计算。主题 class/style、常见 `data-theme` / `data-color-mode` / `data-bs-theme` / `data-mode` 变化、系统主题和窗口变化会更新当前段落，不重新分析文章。只调整扩展自己的高亮规则，不覆盖网站段落背景或原文字色。

配色优先保留主要文字的可读性：原对比达到 4.5 时，合成后仍至少 4.5；原对比偏低时不明显降低。没有安全可见颜色的类型跳过高亮，图片或渐变背景改为仅聚焦。计算依据段落主文字色，不代表所有行内链接、代码或 CSS 滤镜等最终像素效果都已经验证。配色更新不改变分析版本或缓存，已有结果可直接继续显示。

选中英文词语后点击“查词”，先查看释义，再自行决定是否收藏。释义优先来自现有内置英中词库，未命中时尝试已经准备好的浏览器本地翻译；不自动下载语言包。不支持或未准备好时明确显示缺少释义，仍可保存词语及原句后在单词本补充。

退出会移除本模式的属性、样式、扫描元素、高亮、查词浮窗、监听和观察器，已经启动的文章分析在后台继续，完成后保存结果。再次进入同一篇文章时，复用尚未结束的任务或已保存的结果。退出不等于“停止分析”；要停止需使用独立入口。智能框选与本模式互斥，开启智能框选会退出辅助阅读，但不会因此停止后台任务。

v3 使用新的分析缓存版本；旧版已完成结果不会被当作新版效果，再次主动开启时会进行一次新的整篇分析，之后照常缓存。旧版在途和状态不明的同一正文任务仍然阻止重复提交；检查与创建在同一个数据库事务内完成，升级版本也不会绕过这项保护。

正文变化或网页切换后会撤下旧高亮并提示重新开启。重新开启时核对当前正文，再决定能否复用结果，不会把另一份文章的标记套在当前页面。

## 结构与边界

- `src/content/readingFocus/` 在原文档识别正文与阅读块，等待整篇准备完成，维护当前段落、跨文本节点的 Range 和 CSS Custom Highlight。它通过传入的准备、查询和停止方法取得任务状态，不直接依赖 WorkOS，不替换正文或原有内联样式。
- `entrypoints/content.ts` 连接现有选词工具条、查词浮窗和页面状态条；`ReadingFocusButton.tsx` 读取当前标签页状态，提供侧边栏开关。
- `src/background/pageReadingRuntime.ts` 和 `registerPageReading.ts` 复用现有连接凭据及 WorkOS 传输，为一份正文建立独立文章任务，提交整篇一次并保存阶段。同一正文、目标配置的重复开启及多个标签页复用任务；全局最多同时准备两个文章任务。它不使用用户正在提问的远端会话，也不向页脉本地会话添加提问和回答。WorkOS 仍可能保留文章分析会话。
- `src/shared/pageReadingFocus.ts` 定义正文快照、整篇输入输出、状态和原文检查；意群沿用 `src/shared/readingFocus.ts` 的类型。模型只返回段落编号、精确原文片段和类型，不重复回传整篇原文，不依赖模型计算全文偏移。重复片段必须提供准确的出现序号；只接受连续、顺序正确且不重叠的原文片段，不使用模糊匹配。
- `src/data/pageReadingRepository.ts` 将任务及纯数据结果保存在现有 IndexedDB 的 `meta` 表，不修改数据库结构，不进入本地知识备份。结果身份由归一化页面地址、段落编号与文本顺序、分析版本、传输类型、Agent 和固定 API 地址决定，不包含连接凭据。持久缓存最多保留最近 20 个已完成任务；在途和状态不明的记录不因此删除。清理后再次阅读可能需要重新准备。
- `readingWordPopover.ts` 只负责显示及明确的收藏操作；词库查询在后台复用 `lookupWordMeaning`，保存使用现有 `collectWord`。

优先识别 GitHub Markdown、常见文档正文、`article` 和 `main` 等容器；不保证所有页面均可识别。导航、隐藏或可编辑区域、控件和代码块不参与。含代码块或导航的复合块整体跳过，其独立正文子段落仍可识别。

没有 CSS Custom Highlight 支持时只提供本地段落聚焦，不发送 AI 分析请求。支持高亮时，文章最多 60,000 个 UTF-16 单元、240 个阅读段落、单段最多 16,000 个单元；超限明确提示暂不支持完整分析，不截断正文，也不自动拆分成多个远端会话。模型输出最多 240,000 字符，每段最多 32 个片段，全篇最多 1,000 个片段。

每个段落应返回结果或明确的空片段数组。空数组表示有效的“不额外着色”；遗漏、无法精确定位或不符合要求的段落只保留聚焦，界面显示实际准备数量。未知或重复段落编号会拒绝整份响应，避免错配；没有任何段落通过检查则判为失败，不显示整篇准备成功。

当前后台对远端创建与分析设置 5 分钟候选等待上限，替代旧的单段短限时。这个数值用于有限等待，尚未根据真实 WorkOS 和目标文章的耗时验证，不代表服务应在此时长内完成。达到上限时停止本地等待并保留“远端状态不明”，不把本地断开当作远端停止，也不自动重新提交。

## 退出、停止和状态不明

退出界面、普通换段和标签页关闭都不会请求远端停止。显式点击“停止分析”时，如果任务尚未提交，可以结束准备并记录为已停止；已经提交的任务则按当前传输能力处理。

Internal v2 支持请求平台停止，但“停止请求被接受”不等于已确认任务终态。没有终态证据时保存为状态不明，提示在 WorkOS 查看，不把结果显示成“已经停止”。Public v1 没有远端停止方法；提交后点击停止会明确说明限制，继续接收同一任务的结果并缓存，避免断开后丢失它的状态。

已确认失败或停止的任务提供明确重试；尚未取得任务状态的首次准备失败，也可点击重试，由后台查询同一文章的已有记录后决定是否创建。状态不明、在途或已完成的任务都不会通过重复开启自动重提。扩展重载后，原先尚未结束的记录转为状态不明，不自动恢复远端运行或另建会话；用户需要先在 WorkOS 检查。这也适用于等待上限、断流或停止状态无法确认的情况。

模型提示要求不调用工具、不翻译、不生成文件；收到工具、产物或交互事件时尝试停止。提示词与事件检测无法从客户端保证一个任意配置的远端 Agent 永远不会开始执行工具，需要通过真实 Agent 验证其适用性。

状态提示只报告客户端观察到的阶段，不输出凭据或远端标识。“等待分析”或“尚未收到正文”不证明沙箱、模型或其他远端步骤具体停在哪里；部署失败与模型响应慢仍需真实调用记录区分。

## 站内切页地址识别（2026-10-23）

用户在 OpenRouter 文档从 Principles 切到 Models 后重新开启，出现“文章地址与当前网页不一致”。隔离 Chromium 中用真实扩展及 `history.pushState` 复现了同一提示：Chrome 的 `sender.url` 仍为脚本首次注入的 Principles 地址，`sender.tab.url` 与当前正文快照则均为 Models。

后台现在优先用浏览器提供的当前顶层 `tab.url` 核对文章。发送者扩展身份、顶层框架、标签页和文档授权仍需通过；已提供的 tab URL 必须是 HTTP(S)，且与原始 sender URL 同源，否则直接拒绝。没有 tab URL 时保留原行为。每个任务的原文地址仍单独检查，切到新文章不能读取或停止旧文章任务；后退则可复用原文章缓存。不接受页面自行声明地址替代浏览器来源，不新增扩展权限。

修复前的浏览器复现与新增单测均失败于该提示；修复后75项相关单测、TypeScript、构建、原9组扩展流程通过。`scripts/verify-page-reading-extension.mjs <Playwright模块路径> --spa-only` 新增3组真实扩展检查：Principles→Models、后退复用缓存、阅读中 replaceState 后原高亮失效且重进复用新文章缓存。四次进入只提交两个不同文章任务，均使用模拟 WorkOS，没有创建真实会话。证据保存到 `output/playwright/page-reading-extension/spa-checks.json`。OpenRouter 用户原标签页仍需加载本地新构建并刷新一次后实际确认。
