## 真实 Chrome 人工验收

使用 `.output/chrome-mv3` 作为未打包扩展目录。准备一个全新的独立目录和一个已有普通文件的目录。

- [ ] 在 300、360、430 px 三种 Side Panel 宽度下打开设置，目录状态与操作无截断。
- [ ] 从用户点击“选择独立目录”开始打开原生目录选择器；取消选择不改变现有状态。
- [ ] 选择空目录后完成写入、回读、删除探针；目录内不残留 probe 文件。
- [ ] 选择非空目录时出现明确说明；取消确认不连接，确认后不导入也不改写普通文件。
- [ ] 关闭并重新打开 Side Panel 后仍显示目录名；若 Chrome 要求权限，只有点击“重新授权”才触发提示。
- [ ] 形成一条判断原则认知；用户未编辑主问题时不能提交，确认后 Obsidian 可直接读到一个带稳定 `yemai_id` 的 Markdown 文件。
- [ ] 模拟本地写入失败时不显示保存成功；恢复后重试不创建第二个文件。
- [ ] 模拟本地已保存但远端 interrupt resolution 失败，界面显示“已保存到本地，Agent 尚未恢复”，重试只恢复 Agent。
- [ ] 在 Obsidian 修改未知 frontmatter 和非管理正文，再执行保持、修订、待验证；未知内容均保留。
- [ ] 访问另一网页时弱命中只点亮顶部入口，强命中/潜在冲突才显示内联提示；最多三条且不上传目录。
- [ ] 点击顶部弱提示只打开本地认知详情；只有继续点击“与当前材料对照”后才创建瞬时 Agent 请求。
- [ ] 分别完成保持、修订、待验证；Markdown 追加 supported、revised、challenged 事件，重复点击不重复追加。
- [ ] 对照工作台支持 Tab/Shift+Tab 焦点循环、Escape 返回和焦点恢复；减少动态效果设置下无位移动画。
- [ ] 清空会话、删除来源会话、删除阅读卡片、清空 cognition projection、断开目录后，Markdown 文件仍全部存在。
- [ ] 删除一个受管理 Markdown 后重建索引，入口不再展示该认知且不尝试恢复文件。

## 两周产品价值验证

这部分不是发布前的工程验收。连续两周实际使用后再判断产品方向：

- [ ] 主动确认至少 10 条认知，而不是批量保存 Agent 观点。
- [ ] 至少发生 3 次有明确原因的旧知重逢。
- [ ] 至少 1 条认知因新材料被支持、挑战或修订。
- [ ] 回看这些事件时，用户能说明旧认知如何影响了新的阅读或判断。

若只有文件数量增长，却没有旧认知参与新的思考，应停止扩建关系图、自动标签和更复杂检索。
