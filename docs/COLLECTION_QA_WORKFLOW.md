# 收藏问答与 Obsidian 保存

> 当前流程，2026-09-27。以用户认可的独立交互原型为方向；原型是模拟数据，不是验收证据。

## 用户流程

1. 对已完成的回答收藏完整内容，或划选片段收藏。新卡片同时记录直接触发该回答的最近一条用户提问、实际收藏的正文、来源和时间；如果回答使用了多条收藏资料，原问题只记录用户实际输入的提问，原收藏的来源链接也记入来源。旧卡片若仍能找到原对话，可以临时读取原问题；找不到就标记缺失，不让 Agent 猜测。
2. 打开收藏时默认显示卡片河流。瀑布流与列表切换放在收藏标题栏，减少占用空间。列表可勾选多张；切换视图会退出正在阅读的卡片详情，切回河流时仍显示已选数量。主动退出收藏页会清空勾选；由“开启新会话”自动关闭收藏页时暂时保留选择，以便处理提交结果不明的情况。
3. 点击“用所选收藏开启新会话”只创建本地草稿，不请求 WorkOS。新会话显示待发送的问答数量与标题，不自动附加当前网页；用户可以移除这批材料，在普通聊天框里提出具体问题。首次发送时，问题和所选问答及来源一起提交，消息内可展开核对实际材料；不再自动套用“综合整理”任务，也不提供全局提示词设置。材料预留问题字数，总字符超限时要求缩短问题或重新选择。
4. 尚未提问时，所选材料随会话草稿保存，切换工作页或重开侧边栏仍在。收到首次回答正文或产物就说明材料已送达，清空对应勾选；若之后流异常结束，保留已收到内容并提示可能不完整。没有收到任何回答且发送状态不明时保留新会话和原选择，不自动重发。回答仍需用户主动收藏，才会进入后续保存流程。旧版已经发送的固定整理消息仍可在历史中查看。
5. 点击“保存到 Obsidian”时，必要时选择或重新授权知识库里的问答文件夹。每张卡片各新建一个 Markdown，不合并、覆盖、修改或删除既有文件。文件包含问题、实际收藏的回答或片段、来源、收藏时间和完整收藏 ID。
6. 文件名为收藏日期加问题标题；同名文件加 `-2`、`-3` 等序号。重复判断只看文件元数据里的完整 `yemai_card_id`，因此在 Obsidian 改名后仍能识别。批量保存逐项继续，报告已新建、已存在和未保存；仅未保存项保持勾选。旧卡片缺原问题时跳过并说明。用户删除文件后，只有再次主动点击保存才会新建。

## 文件与权限边界

- 问答目录使用新的浏览器目录连接，不复用旧的 `yemai` 认知目录句柄，也不移动任何旧文件。用户应在 Obsidian 库内自行新建并选中目标文件夹。
- 浏览器目录授权本身是读写权限。“只新增”是页脉代码的行为限制：写入前扫描目标文件夹内的 Markdown，检查完整收藏 ID 和文件名，随后仅调用新建文件写入。浏览器 API 不提供对外部程序并发创建同名文件的事务级排他保证。
- 扫描失败时整批停止写入，以免无法判断重复。单个文件新建失败时继续其他卡片，并保留失败项供用户处理。
- 浏览器本地备份保存卡片和会话；Obsidian 文件由用户在知识库中备份。断开目录连接只移除浏览器保存的句柄，不动目录或文件。

## 旧流程退役

对话中的认知候选、回执显示、重遇提示、目录扫描与改写流程已移除；旧专门文档与原型也已删除。历史会话原始数据和既有 Markdown 不清理。数据库升级只删除可重建的旧认知索引表；旧目录句柄不迁移给新问答目录。

## 验证范围

自动检查覆盖最近问题提取、片段原文、待提问草稿的保存与恢复、按用户问题发送材料、同标题序号、重命名后的 ID 判重、部分失败和扫描失败停止写入。生产构建与 TypeScript 检查验证代码可打包。真实 Chrome 目录授权、Obsidian 可见性以及 WorkOS 实际新会话仍需在安装扩展后人工验证；自动测试或原型不代表这些外部环节已验收。
