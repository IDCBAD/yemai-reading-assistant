# 收藏问答与 Obsidian 保存

> 当前实现，2026-10-21。收藏引用与紧凑操作布局已接入正式组件；本地组件验证与安装扩展后的 Chrome / WorkOS 验收分开记录。

## 用户流程

1. 对已完成的回答收藏完整内容，或划选片段收藏。新卡片同时记录直接触发该回答的最近一条用户提问、实际收藏的正文、来源和时间；如果回答使用了多条收藏资料，原问题只记录用户实际输入的提问，原收藏的来源链接也记入来源。旧卡片若仍能找到原对话，可以临时读取原问题；找不到就标记缺失，不让 Agent 猜测。
2. 打开收藏时默认显示卡片河流。瀑布流与列表切换使用分类导航右侧的两个图标，不再独占一行。列表可勾选多张；切换视图会退出正在阅读的卡片详情，保留勾选，回到列表可以继续批量操作。由“开启新会话”自动关闭收藏页时暂时保留选择，以便处理提交结果不明的情况。
3. 点击“用所选收藏开启新会话”只创建本地草稿，不请求 WorkOS。新会话显示可查看、排除、移除的收藏材料，不自动附加当前网页；用户在普通聊天框里提出具体问题。首次发送时，问题和所选问答及来源一起提交，消息内可展开核对实际材料；不再自动套用“综合整理”任务，也不提供全局提示词设置。
4. 尚未提问时，所选材料随会话草稿保存，切换工作页或重开侧边栏仍在。收到首次回答正文或产物就说明材料已送达，清空对应勾选；若之后流异常结束，保留已收到内容并提示可能不完整。没有收到任何回答且发送状态不明时保留新会话和原选择，不自动重发。回答仍需用户主动收藏，才会进入后续保存流程。旧版已经发送的固定整理消息仍可在历史中查看。
5. 点击“保存到 Obsidian”时，必要时选择或重新授权知识库里的问答文件夹。每张卡片各新建一个 Markdown，不合并、覆盖、修改或删除既有文件。文件包含问题、实际收藏的回答或片段、来源、收藏时间和完整收藏 ID。
6. 文件名为收藏日期加问题标题；同名文件加 `-2`、`-3` 等序号。重复判断只看文件元数据里的完整 `yemai_card_id`，因此在 Obsidian 改名后仍能识别。批量保存逐项继续，报告已新建、已存在和未保存；仅未保存项保持勾选。旧卡片缺原问题时跳过并说明。用户删除文件后，只有再次主动点击保存才会新建。

## 在当前问题中引用收藏

1. 点击输入区“引用收藏”，按收藏标题、原问题、正文或来源搜索。可先查看原问题、收藏正文及来源，再单条或批量加入。选择跨关键词搜索保留；已有材料显示已加入，不重复添加，也不替换已有快照或排除选择。
2. 加入只修改当前会话草稿，不创建新会话、不发送请求；已输入的问题以及原有网页、划词、附件保持原样。每条收藏可查看完整快照、排除本次引用或移除。排除只影响本次发送，不删除收藏。
3. 正常会话按原有页面提供规则准备网页，收藏与页面、划词一起组装为通用的 `yemai.context.v1` 引用资料。收藏包括原问题、实际收藏的回答或片段、来源；缺失的旧问题明确标记，不补造。材料中的指令作为引用内容，保留用户实际提问。
4. 草稿随会话保存在 IndexedDB，并进入本地备份；旧草稿没有 `included` 时默认引用。发送时复制所选材料和来源，之后修改或删除原收藏不会改变已发送内容。已引用收藏从草稿清除，排除项继续保留；回答下“本次上下文”可核对提供过的收藏。它说明材料已提供，不保证 Agent 采纳。
5. 加入时所选收藏上限为 28,000 字符；发送前对实际组合后的问题、收藏、网页和会话背景检查 30,000 字符上限，不默默截断收藏。若网页准备后才发现超限，不请求远端 Agent，说明本次未发送，将收藏放回输入区并保留已写的新草稿。附件仍走原有独立上传方式，产物文件本体不会因为引用收藏而再次上传。

搜索、选择、快照和保存由插件负责，收藏输入类型定义在共享上下文模型中；现有 WorkOS 只接收组装后的文字及附件。未来替换 Agent 时，可以复用这些能力，在传输部分适配新服务的输入方式。

## 文件与权限边界

- 问答目录使用新的浏览器目录连接，不复用旧的 `yemai` 认知目录句柄，也不移动任何旧文件。用户应在 Obsidian 库内自行新建并选中目标文件夹。
- 浏览器目录授权本身是读写权限。“只新增”是页脉代码的行为限制：写入前扫描目标文件夹内的 Markdown，检查完整收藏 ID 和文件名，随后仅调用新建文件写入。浏览器 API 不提供对外部程序并发创建同名文件的事务级排他保证。
- 扫描失败时整批停止写入，以免无法判断重复。单个文件新建失败时继续其他卡片，并保留失败项供用户处理。
- 浏览器本地备份保存卡片和会话；Obsidian 文件由用户在知识库中备份。断开目录连接只移除浏览器保存的句柄，不动目录或文件。

## 旧流程退役

对话中的认知候选、回执显示、重遇提示、目录扫描与改写流程已移除；旧专门文档与原型也已删除。历史会话原始数据和既有 Markdown 不清理。数据库升级只删除可重建的旧认知索引表；旧目录句柄不迁移给新问答目录。

## 验证范围

自动检查覆盖最近问题提取、片段原文、待提问草稿的保存与恢复、按用户问题发送材料、同标题序号、重命名后的 ID 判重、部分失败和扫描失败停止写入。生产构建与 TypeScript 检查验证代码可打包。真实 Chrome 目录授权、Obsidian 可见性以及 WorkOS 实际新会话仍需在安装扩展后人工验证；自动测试或原型不代表这些外部环节已验收。

收藏引用新增检查覆盖去重、排除与移除、来源复制、发送快照、备份恢复、网页与划词混合输入、旧问题缺失和材料分隔标记。`node scripts/serve-collection-reference-preview.mjs` 启动真实侧边栏组件的本地验证页（端口 5193），使用独立 localhost 存储、合成收藏及模拟 Agent，所有 WorkOS 请求在本地拦截；不读取真实扩展凭据。追加 `?scenario=capacity` 可验证网页与收藏组合超限，完整回答是否被远端 Agent 正确使用仍需真实扩展验证。

## 收藏页快捷操作（2026-10-21）

问答收藏导航右侧使用层叠卡片 / 列表图标切换，保留原有 view 状态。导出全部和回到最新集中在卡片区域右下角的 40px 浮动按钮内；正常高度沿左上四分之一圆弧展开，220ms 位移、轻缩放和透明度过渡。鼠标悬停或键盘焦点显示名称，点击操作后收起。主按钮、外部点击、焦点离开、Esc 均可收起；键盘和减少动态效果设置下不播放位移动画。

瀑布流仍使用原 nearestReadingCardRiverPosition 定位和速度清零逻辑，新增的状态通知仅在“是否位于最新”变化时更新 React。列表定位只滚动自身容器到顶部，不清空勾选。处于最新时隐藏定位操作，导出移到中间；空收藏、词卡分类、打开全文时不显示菜单。列表菜单独立放在卡片视口内，底部批量按钮不被遮挡。ResizeObserver 根据视口调整圆弧距离，极矮时转为横向排列。

在现有 localhost 真实组件页验证 280 / 320 / 440px 导航不换行、菜单打开关闭与键盘焦点、河流回到 1/9、列表从 scrollTop 250 回到 0 且保留所选、全文展开与分类切换、空收藏。280px 宽、列表视口约 75px 高时，两个操作均完整位于视口内且中心命中自身按钮。菜单实际调用正式 Markdown 导出服务，Downloads 中生成 3651 字节文件，核对包含全部 9 张合成卡片及来源。完整自动检查 106 文件 / 712 项通过；最终菜单尺寸补充后 TypeScript、相关 34 项与生产构建通过，无新增依赖或权限。构建约 13.70 MB。未重新加载真实安装扩展，不将 localhost 检查称为真实侧栏验收；未提交或推送。
