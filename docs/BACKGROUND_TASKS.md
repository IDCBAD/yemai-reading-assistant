# 关闭侧边栏后继续执行

2026-10-11 用户报告最新表单与提醒测试暂无问题，并授权合并提交当前进度。本文件记载的能力纳入本次 `main` 整合提交；下方“未提交”是各次测试结束时的历史状态，未创建新版本 Release。网络断流原因、自动重连与历史缺失内容恢复的验证边界保持原记录。

2026-10-09 本地实现，尚未提交或发布。用户已批准后台持续执行、重开时保留实时进度，以及默认启用系统通知、工具栏数字和对话未读圆点。三种提醒已接入，真实系统弹窗仍待验收。

## 使用行为

- 点击发送后，扩展后台接管当前问题和排队问题。关闭侧边栏只断开显示页面，不取消后台请求。重新打开后恢复正在生成的回答、工具进度、产物和待确认表单。
- 侧边栏保持打开时，后台空闲休眠或重启不会永久禁用切换。下一次操作恢复订阅，尚未确认的草稿和切换按原顺序迁移；旧后台迟到的响应不覆盖新状态。通信中断和实际保存失败分别处理，真正保存失败仍阻止后续发送。
- 输入资料随这一次提问固定：已有正文快照直接传递；需要读取的页面使用发送时的浏览器标签页 ID 和 URL，在后台接单时开始提取，排队期间不会再去读后来切换的页面。页面关闭或 URL 变化时保留链接并显示正文读取失败。
- 附件必须上传完成后发送。未发送的文件上传仍在侧边栏执行，不承诺关闭侧边栏后继续上传。
- 显式暂停仍调用 internal-v2 的 WorkOS `/action/abort`。点击暂停后立即关闭侧边栏，后台继续等待结果并保存；同会话队列等待暂停处理结束。暂停未确认时后续排队问题不自动发送。
- 浏览器关闭、扩展禁用/重载或后台异常终止会使连接中断。重启后保留已经保存的部分结果，提示远端状态未确认；排队问题不会自动重发。本轮没有提供断线后重新订阅旧 WorkOS 任务的能力。
- 清空历史和连接设置变更会结束当前本地接收；沿用原有普通清理语义，不把它们当作 WorkOS 显式暂停。删除历史也不调用 WorkOS 暂停接口。
- 活动任务期间不能导入备份。导入期间后台拒绝会话修改，导入结束重新加载记录。导出先要求后台保存最新状态。

## 运行和保存

```text
侧边栏
  输入、阅读材料、界面操作
  ↓ 立即发送按序命令
扩展 Service Worker
  会话队列 → WorkOS 请求 → 文本/工具/产物/交互事件
  ↓                         ↓
IndexedDB 保存          向已打开界面发布最新状态
  ↓
重新打开侧边栏：读后台快照，然后接收后续进度
```

后台统一拥有会话持久化和执行状态。侧边栏只发送实际修改的字段，不再把整个旧工作区保存回数据库。正在运行的消息、远端会话身份和来源送达记录由后台更新。快照包含后台实例、版本及每个客户端已处理的操作序号；界面拒绝旧快照，并重放尚未被快照包含的本地输入。操作和新增消息按 ID 去重。

提问记录保存成功后才调用 WorkOS。真实派发时记录已处理序号，即使后续保存失败，同一操作也不会重复提交。保存失败时向界面报告未保存状态，每 5 秒重试，任务结束后最多继续重试 90 秒；持续失败不会承诺重启后保留尚未落盘内容。

Chrome 会休眠空闲 Service Worker。这里沿用 Chrome 官方对有限长操作的建议：有任务或有限保存重试时每 25 秒调用 `runtime.getPlatformInfo()`，结束后清理定时器。每条开始执行的任务最多接收 6 小时，包括人工确认等待；达到上限主动进入暂停处理。后台不是永久运行的浏览器服务。官方说明见 [Service Worker 迁移指南](https://developer.chrome.com/docs/extensions/develop/migrate/to-service-workers#keep-the-service-worker-alive) 和 [生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)。

后台不能动态 `import()`，因此传输模块采用静态导入。原 `jsencrypt` 在 Worker 缺少 `window.crypto` 时可能退回非安全随机数，身份加密已替换为使用 `crypto.getRandomValues()` 的 RSAES-PKCS1-v1_5 模块，保留原公钥和请求格式；没有安全随机源时明确失败。

完成、失败和待确认事件与已读状态在同一个 IndexedDB 事务中保存，带稳定事件 ID，最多保留最近 100 条。通知中心独立处理显示，浏览器通知错误不会改变任务结果或阻止后续发送。提醒记录暂时保存失败会保留待处理事件，每 5 秒重试，最多自动重试 3 次；打开界面也会重新尝试。存储持续不可用且后台重启时不能保证尚未落盘的提醒恢复。

## 三种提醒

- 默认开启系统通知：任务完成、失败或需要人工确认时，显示状态和本次提问摘录，不展示回答正文。摘录按该事件对应的回答查找前一条用户提问，合并换行、最多 100 个 Unicode 字符；纯附件或空提问回退到会话标题。后续排队问题不会替换正在完成任务的提醒内容。正常生成进度不弹通知。
- 工具栏数字表示有未读事件的会话数量，同一会话多个事件只计一个。插件需固定到浏览器工具栏才能持续看到；鼠标悬浮也显示未读会话数量。
- 工作页编号左上角静态圆点表示该会话有未读任务结果，右上角现有动画圆点仍表示正在生成，两者分开显示。
- 仅当对话实际显示、页面可见且获得焦点，并且没有设置、收藏、搜索等遮挡层时，标记已查看。打开插件不清除其他对话的提醒；查看报告按具体事件 ID 清除，迟到的报告不清除新事件。
- 设置中的“系统通知”开关默认开启，关闭后保留工具栏和对话角标。重新开启不会补弹旧事件。浏览器拒绝通知权限时，设置说明角标仍可使用。系统设置可能影响真实弹窗显示。
- 工具栏角标设置黑色背景、白色数字，数字仍按未读会话数计算。外形由 Chrome 原生 Action 角标绘制，API 没有自定义圆角参数。
- 点击系统通知优先同步尝试打开所在窗口的侧边栏，再定位对应会话；窗口失效或 Chrome 不接受该打开方式时，使用带目标参数的扩展页面。工作页已满时复用当前入口，原会话数据留在历史；明确点击归档会话的通知时恢复该会话。删除目标会话后清理失效提醒。
- 通知和点击目标均有事件/操作版本。旧通知超时后即使晚到，也只清理自身，不覆盖或删除较新的通知。后台重启恢复未读角标，不补弹旧通知；接入前的历史事件视为已读。

扩展新增 `notifications` 权限；重新加载或更新时 Chrome 可能要求接受权限。API 最低 Chrome 116 与当前项目一致。官方说明见 [Notifications API](https://developer.chrome.com/docs/extensions/reference/api/notifications)、[Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) 和 [Action API](https://developer.chrome.com/docs/extensions/reference/api/action)。官方资料没有明确保证每个 Chrome 版本都接受通知点击作为侧边栏打开手势，因此保留扩展页备用路径。

## 长时间打开后切换失效的修复

用户报告侧边栏打开一段时间后点击工作页不生效，关闭再打开恢复。旧实现把端口断开和后台实例变化保存成不可恢复的客户端错误；后台也把旧实例的修改请求拒绝计为保存失败，导致同一客户端之后仍被拒绝。修复后按后台实例和操作序号确认修改，新实例立即合并迁移尚未确认的界面操作。多个通信请求同时失败时等待同一个重连，不使正在连接的新端口失效。

仅恢复草稿、切换和问题记录，不自动重发提交、人工确认或清理命令。重启时新问题如果只有未确认的本地记录，回答显示停止并提示“本次发送未确认，请检查 WorkOS 任务状态后再重试”，避免一直显示排队或重复运行。

提醒方案已按用户确认接入，显示和清除规则见上文。

### 通知失败误报与提示内容修复（2026-10-11）

只读检查现场插件数据库确认：用户截图对应的数次任务已有回答正文，但本地状态保存为 `failed`，原因为“Agent 执行失败”。普通失败原因在已有正文时不会显示，因此界面看起来已正常结束。随后使用独立的简短 WorkOS 测试会话确认实际终态是 `run.terminal` 的 `status: "run_succeeded"`，并收到了完成标记；旧解析器仍触发失败回调，因为成功白名单没有该状态。

### 长任务进度断流的处理（2026-10-11）

用户报告关闭侧边栏后，约 3 分 23 秒出现失败通知，但 WorkOS 仍运行并最终完成。已用合成流读错误复现同一网络文案；尚不能确认现场断流由网络、代理、服务端还是浏览器触发。代码没有三分钟任务截止条件，后台总时限仍为六小时。

内部 v2 提交已成功且有 runId 后，读取进度异常或未收到完成事件的 EOF 改为 `WorkosProgressDisconnected`。明确远端错误优先，主动暂停流程保持原有行为。接收结束不等于远端任务失败或暂停。

后台保存部分结果和未确认运行的会话 UUID、runId、Agent、接口来源与断流时间。未收到结束状态的工具显示“状态未确认”，不伪造工具结束时间；已经确认的完成/失败保留。已有排队问题标记未发送；同一远端目标暂不接受新问题，原会话可编辑草稿，新问题可另开对话。换 Agent 或通道后创建新远端目标不受旧标记影响。配置读取、保存期间发生断流也会再次检查，被拒绝的问题不会一直显示排队。原会话的限制目前需要后续恢复接口接入才能解除，平台任务自行完成不会自动解除本地限制。

断流独立产生 `connection-lost` 事件，继续通知和角标，标题为“进度连接中断，任务状态未确认”，正文说明 WorkOS 可能仍在运行。不发失败或完成通知，不重发原问题，不调用远端暂停。
