# Chrome 侧边栏 AI 阅读助手：实施与验收计划

## 1. 实施原则

开发顺序为：

```text
文档确认
→ 可交互前端原型
→ 会话与 Tab 模型重构（已完成）
→ 划词与页面抽取
→ API 数据契约
→ WorkOS 集成
→ 本地持久化与安全
→ 联调验证
```

优先验证信息架构、用户路径和组件状态，不在界面尚未确定时提前建设复杂后台逻辑。

实际执行中，在交互原型确认后优先完成了 WorkOS 最小真实链路，用于尽早验证扩展跨域请求、Token、安全边界和 SSE 可行性。联调后确认旧版“多 Tab 共享会话”模型不适合干净并行任务，因此会话模型重构成为页面能力与文件上传之前的下一阶段。

## 2. 阶段一：交互原型

### 目标

使用模拟数据完成可操作的 Side Panel，确认界面密度、会话模型、页面状态、引用和附件体验。

### 实现范围

- WXT + React + TypeScript 工程
- 全局 Side Panel 入口
- 模拟会话列表与切换
- 旧版会话内多 Tab 的新增、切换与右键关闭
- 新建本地草稿会话
- 当前页面状态卡片
- 引用添加、删除和去重
- 模拟附件及状态
- 消息输入与模拟流式回复
- 停止生成
- Markdown 和代码块展示
- 清空历史确认界面
- Token 设置界面，但不调用 API

### 不实现

- Content Script
- 页面正文提取
- 真实文件读取和上传
- WorkOS API
- 真实本地持久化

### 验收

- 侧边栏宽度 320–520px 时信息不溢出。
- 键盘可以完成核心操作。
- 按钮、输入框和弹层具有清晰焦点状态。
- 高频操作无冗长动画。
- 会话管理按钮集中在输入工作台，历史会话以输入框上方的悬浮抽屉呈现。
- 切换 Tab 后能恢复该 Tab 的消息视图、输入草稿、引用和附件。
- 模拟流式过程中发送按钮变为停止按钮。
- 引用和附件删除不会误删其他项目。
- 空会话、失败、无页面和页面变化状态均可演示。

## 3. 阶段二：会话与 Tab 模型重构（已完成）

### 目标

把旧版“一个会话包含多个 Tab”调整为“一个 Tab 打开一个独立会话”，使 UI 窗口、WorkOS `conversationUuid`、本地历史和分支语义一一对应。

### 实现范围

- 新增 `OpenConversationTab`，只保存本地 Tab ID 与 `conversationId`
- `LocalConversation` 直接持有消息、草稿、页面来源和唯一 `remoteUuid`
- `+` 创建新 Tab 和独立草稿会话
- “新对话”在当前 Tab 中创建草稿会话，原会话保留在历史中
- 历史选择未打开会话时加载到当前 Tab
- 历史选择已打开会话时直接定位到已有 Tab
- 最多同时打开 10 个 Tab，达到上限后禁用 `+`
- Tab 条横向滚动，当前 Tab 自动滚动到可见区域
- 关闭 Tab 不删除会话历史或远端会话
- 分支使用新的独立会话，并保存结构化父子关系与序号
- 分支基础标题保持稳定，不重复拼接“· 分支”
- `workspaceState` 升级版本并迁移旧的多 Tab 快照

### 迁移策略

- 一个旧外层会话迁移为一个新会话，保留原 `remoteUuid`
- 旧 Tab 的已发送消息按时间合并，并保留页面来源
- 活跃旧 Tab 草稿迁入主会话
- 其他旧 Tab 的未发送草稿转换为独立本地草稿会话，禁止静默丢失
- 迁移失败时保留旧快照，不覆盖原数据

### 验收

- 不同 Tab 第一次发送后获得不同的 `conversationUuid`
- 一个会话不会同时出现在两个 Tab；从历史重复选择时直接定位
- 保持同一 Tab 切换浏览器网页时，会话记忆连续，页面来源增加
- 第 10 个 Tab 可正常使用，第 11 次新增被禁用并给出原因
- 窄侧边栏下 Tab 可横向滚动，激活 Tab 始终可见
- 关闭 Tab 后会话仍在历史中，并能重新加载
- 分支标题不会出现“分支 · 分支”，历史能识别父会话和分支序号
- 旧版持久化快照升级后，会话、消息、UUID 和未发送草稿均不丢失

### 实施结果

- 工作区快照升级为 v2，并实现 v1 显式迁移与中断流恢复。
- 每个打开 Tab 只绑定一个独立会话；新建 Tab 不再复用当前 `conversationUuid`。
- 不同会话可分别维持流式请求，切换或关闭窗口不会误停其他会话。
- 10 个 Tab 上限使用真实 disabled 状态；Tab 条横向滚动并自动保持激活项可见。
- 历史选择已打开会话会定位到已有 Tab，未打开会话会替换当前窗口绑定。
- 分支保存根会话、父会话、分支点和稳定序号，标题不再重复追加“· 分支”。
- 单元测试、TypeScript 检查、生产构建及 726×1080 浏览器交互检查均通过。

## 4. 阶段三：浏览器页面能力（普通网页闭环已完成）

### 目标

完成真实划词、Side Panel 打开与正文抽取。

### 实现范围

- Content Script 选区监听（已完成）
- 轻量悬浮入口（已完成）
- Side Panel 在线状态协调（已完成，MVP 按浏览器实例判断）
- 待处理引用队列（已完成，`chrome.storage.session`）
- Readability + Turndown 正文抽取（已完成）
- 页面哈希和版本（已完成基础记录）
- X 单条推文渐进适配
- 不支持页面提示（已完成基础降级）

### 当前结果

- 普通 HTTP/HTTPS 页面可读取标题、站点、URL 和主要正文。
- 侧边栏关闭时，划词后出现 30px 轻量引用入口；侧边栏打开时直接加入当前会话草稿。
- 关闭期间的引用通过会话级队列暂存，侧边栏打开后消费并去重。
- 当前会话第一次针对页面发送时附带全文；后续消息默认只发送问题与新引用。
- 用户可显式“重新读取”，新版正文随下一条消息注入。
- 页面正文限制为 40,000 字符，不写入持久化快照。
- 历史抽屉新增本地归档与恢复；已打开会话不能归档。

### 验收网页

- AI Agent 教程页
- 一个普通官网文章页
- 一个技术博客页
- X 单条推文详情页
- X 线程页
- 一个无法注入内容脚本的受限页面

## 8. 原型视觉方向

### 设计主题

产品不是通用聊天机器人，而是“贴着网页工作的阅读批注台”。视觉语言应接近研究笔记和文本编辑器，而不是营销型 AI 面板。

### 布局概念

```text
┌────────────────────────────┐
│ 页边 · 当前会话       设置 │
│ 当前来源 · 已读入          │
├────────────────────────────┤
│                            │
│ 对话正文                   │
│ 引用在消息中保留来源       │
│                            │
├────────────────────────────┤
│ [会话1][会话2] + 新对话 历史│
│ [引用 1] [引用 2]          │
│ [附件]                     │
│ 输入问题……           发送  │
└────────────────────────────┘
```

### 视觉原则

- 背景使用偏冷的纸白，而不是常见暖米色 AI 模板。
- 正文以高可读性的系统无衬线字体为主，引用使用窄栏和来源标记建立“批注”感。
- 以深墨蓝和电光蓝作为主要强调色，表示当前来源和正在读取状态。
- 圆角克制，避免所有区域都变成悬浮卡片。
- 将“当前来源书签”作为标志性元素，用一条细竖线贯穿页面状态与引用来源。
- 输入区使用轻微抬升的工具台层级，Tab 与会话操作共用一条紧凑控制带。
- 使用 Koboyo 手绘 SVG 图标形成识别度；只打包实际使用的图标，不依赖运行时外链。
- 高频切换和输入不做位移动画；只为引用加入、状态变化和模拟流式光标提供短反馈。

## 9. 后续决策点

完成原型后再确认：

- 侧边栏信息密度和历史会话入口方式
- 当前页面状态是否足够醒目
- 引用卡片是否应默认折叠长文本
- 文件入口放置方式
- 是否在下一版本加入“总结、解释、翻译”快捷操作
- 页面正文硬上限及超长页面处理方式
